# Ames Housing price prediction

Midterm project for ML Zoomcamp 2026.

I built a small service that estimates the sale price of a house in Ames, Iowa, from its
characteristics. The goal is to give buyers and sellers a quick reference price before
they start negotiating.

## The problem

House prices are hard to judge. A seller who asks too much watches the listing sit
there, and a seller who asks too little leaves money on the table. Buyers have the same
problem in reverse. A model trained on past sales can give both sides a starting point.

The service receives a JSON with the house features and returns an estimated price in
USD. It also returns the prediction in log space, because that is what the model
actually predicts.

- Task: regression
- Target: `SalePrice`, modelled as `log1p(SalePrice)`
- Metric: RMSE on the log target, plus RMSE in USD so the error is easier to read

## Data

I used the Ames Housing dataset (Dean De Cock), downloaded from OpenML
(`house_prices`). The CSV is committed in `data/AmesHousing.csv`.

- 1,460 rows and 81 columns: `Id`, 79 features and `SalePrice`
- 36 numeric features and 43 categorical ones
- 19 columns have missing values, mostly `LotFrontage`, `GarageType` and the basement
  quality columns

## What I found in the EDA

`SalePrice` is right skewed (skew 1.88), so I trained on `log1p(SalePrice)`, which brings
the skew down to 0.12. The strongest numeric correlations with the price are
`OverallQual` (0.79), `GrLivArea` (0.71), `GarageCars` (0.64) and `TotalBsmtSF` (0.61).
The notebook has the distributions, the missing value table and the correlation chart.

## Models

I tuned four models with 5-fold cross-validation and compared them on a validation
split. I only touched the test set at the end.

| Model | CV log RMSE | Test log RMSE | Test RMSE (USD) |
|---|---|---|---|
| Ridge, alpha=50 | 0.1414 | 0.1392 | 26,270 |
| HistGradientBoosting | 0.1306 | 0.1346 | 27,919 |
| GradientBoosting | 0.1267 | 0.1336 | 28,308 |
| RandomForest | 0.1473 | 0.1457 | 29,334 |

GradientBoosting had the best CV score, but Ridge won on the validation split and was
also the best in dollars, so I kept Ridge. It is simpler to explain and much faster to
train.

Final numbers on the test set: R2 = 0.896 and RMSE = US$ 26,270. The mean baseline has
a log RMSE of 0.433, so the model is doing something useful.

## Running it locally

I used Python 3.13.

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt

python train.py
uvicorn predict:app --port 9696
```

Health check:

```bash
curl http://localhost:9696/health
```

Prediction. You can send any subset of the 79 features; missing values are imputed.

```bash
curl -X POST http://localhost:9696/predict \
  -H "Content-Type: application/json" \
  -d '{"OverallQual": 7, "GrLivArea": 1710, "GarageCars": 2, "TotalBsmtSF": 856, "YearBuilt": 2003, "Neighborhood": "CollgCr"}'
```

The answer is `{"predicted_price": 137999.66, "predicted_log_price": 11.835, "currency": "USD"}`.

## Docker

```bash
docker build -t ames-housing:1.0 .
docker run --rm -p 9696:9696 ames-housing:1.0
```

## Kubernetes

I tested it on a local kind cluster:

```bash
kind create cluster --name ames
kind load docker-image ames-housing:1.0 --name ames
kubectl apply -f k8s/
kubectl rollout status deployment/ames-housing
kubectl port-forward svc/ames-housing 9697:80
```

The Deployment runs 2 replicas with readiness and liveness probes on `/health`. The
cluster returned the same prediction as the local API. I left the commands and outputs
in `k8s/evidence.md`.

## Notes

The dataset is small and comes from a single city, so I would not use this model in
another market without retraining. The service also returns a single number, not a
range. If I had more time I would add quantile regression to give a price interval and
deploy it to a managed service so it has a public URL.
